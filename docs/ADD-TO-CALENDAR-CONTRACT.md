# Add to Calendar contract

**Status:** accepted implementation contract for 0.7.0
**Accepted:** 28 August 2026
**Applies to:** shortcode, Gutenberg, Elementor, Divi 5 and optional native fallback

This contract defines the bounded one-way calendar portability accepted in
ADR-085 and ADR-092. It deliberately describes one public event occurrence at a
time. It is not a subscription, synchronization or recurrence-export feature.

## 1. Product boundary

The component may offer three allowlisted destinations:

- a standards-based `.ics` download generated by the site;
- a prefilled Google Calendar compose link;
- a prefilled Outlook on the web compose link.

The local ICS provider is the default. Google and Outlook are deliberate author
opt-ins because following either link discloses the visible event snapshot to the
selected external calendar service. The plugin itself performs no remote request.

The component is atomic and optional. It is available as:

- `[wpse_add_to_calendar]`;
- one dynamic Gutenberg block;
- one Elementor widget;
- one native Divi 5 module;
- one explicitly enabled native-fallback field.

Removing or omitting the component removes all calendar actions. No builder,
block or theme template receives forced markup. The native fallback setting is
off by default and is ignored when Elementor or another supported template owner
renders the single-event body.

## 2. Eligible source

An action exists only for one complete, public and password-free snapshot:

| Context | Result |
|---|---|
| Published one-off event with a valid date | Eligible |
| Exact active recurring-occurrence leaf | Eligible for that occurrence only |
| Recurring series page or explicit recurring-series selection | No output |
| Cancelled one-off event or cancelled occurrence | No output and export returns 404 |
| Draft, pending, private, trashed or password-protected event | No output and export returns 404 |
| Missing, stale, corrupt or dirty occurrence projection | No output and export returns 404 |
| Invalid event ID, occurrence key, method or request shape | No output and export returns 404/405 |

The existing public event and exact-occurrence resolvers own eligibility. An
adapter may not infer the next occurrence from a series, expand a recurrence rule
or fall back from an invalid occurrence to canonical series data.

An explicit event selection on an ordinary page is useful for one-off events.
Exact recurring occurrences remain current-context only in 0.7.0; builders do
not store an occurrence key that can become stale or appear to select a series.

## 3. Immutable normalized snapshot

One request-local resolver creates a value object containing only:

- canonical event ID and stable occurrence public key;
- immutable series UID and occurrence identity;
- effective public title and canonical event/occurrence URL;
- exact validated date range, all-day flag and captured timezone;
- effective scheduled or postponed status;
- bounded plain-text description;
- bounded plain-text venue/address location;
- deterministic last-modified UTC value.

Occurrence title, note, venue and address overrides replace inherited series
values through the existing occurrence presentation boundary. Body, excerpt and
taxonomies remain canonical series data. The description uses the effective
occurrence note when present, otherwise the public excerpt; it always includes
the canonical event URL. HTML, blocks, shortcodes and control characters are not
exported.

The snapshot builder limits title, description and location before provider URL
encoding and ICS generation. Truncation is UTF-8 safe. No adapter reads raw event
metadata or post fields after the snapshot exists.

## 4. ICS contract

ICS output follows [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) and contains
one `VEVENT` in one `VCALENDAR`:

- `VERSION:2.0`, a fixed plugin `PRODID`, `CALSCALE:GREGORIAN` and
  `METHOD:PUBLISH`;
- stable `UID:wpse-{public-key}@mime-simple-events-calendar`;
- deterministic UTC `DTSTAMP` and `LAST-MODIFIED` from the canonical modified
  instant rather than the visitor request time;
- escaped `SUMMARY`, optional `DESCRIPTION`, optional `LOCATION` and canonical
  `URL`;
- `STATUS:CONFIRMED` for scheduled and `STATUS:TENTATIVE` for postponed events;
- `TRANSP:OPAQUE`;
- UTC `DTSTART`/`DTEND` for timed events;
- local `VALUE=DATE` boundaries for all-day events, with the inclusive WordPress
  end converted to RFC 5545's exclusive `DTEND` date.

A zero-duration timed event emits `DTSTART` without inventing an end time. Google
and Outlook compose providers are omitted for that snapshot unless verified to
accept a truthful zero-duration range; the local ICS download remains available.

Content lines use CRLF, end with CRLF, escape backslash, comma, semicolon and
newlines, fold at 75 octets without splitting a UTF-8 sequence and never accept a
dynamic property name or parameter. Organizer, attendee, alarm, recurrence,
HTML, attachment and vendor-specific timezone components are not generated.

The stable UID helps a calendar client recognize a later snapshot, but the UI and
documentation must not promise updates, deduplication or synchronization after
import.

## 5. Download endpoint

The same-origin public endpoint uses an allowlisted GET/HEAD query shape and the
`template_redirect` lifecycle. It requires:

- `wpse_calendar_export=ics`;
- one positive `wpse_event` ID;
- either no occurrence value for a one-off event or one exact 32-character
  lowercase occurrence public key.

No rewrite flush, nonce, cookie or authenticated REST session is required for a
public read. The endpoint re-resolves eligibility on every request. It does not
trust a previously rendered URL and never serves a recurring series page as a
one-off fallback.

Successful responses use:

- `Content-Type: text/calendar; charset=utf-8`;
- a sanitized bounded `.ics` attachment filename;
- `X-Content-Type-Options: nosniff`;
- no-cache/no-store headers so a changed or newly protected event is not retained
  by a shared cache;
- the body only for GET; HEAD returns the same safe headers without a body.

Invalid or ineligible resources receive an ordinary non-disclosing 404. Methods
other than GET/HEAD receive 405. PHP warnings, internal IDs beyond the requested
event ID, projection state and validation details never enter the response.

## 6. Provider links

Google uses its documented one-off prefilled-event route with UTC dates and, for
an IANA event timezone, matching start/end timezone hints. The accepted query
fields are title, dates, description and location only. The provider behaviour is
described by [Google Calendar's one-off prefilled event documentation](https://developers.google.com/workspace/calendar/api/concepts/inviting-attendees-to-events).

Outlook uses its current web compose deep link with subject, UTC start/end, body,
location and all-day state. Microsoft does not publish an equally stable
parameter contract for this unauthenticated compose route. Outlook is therefore
an optional best-effort adapter, covered by browser interoperability tests and
isolated behind one provider builder. If that route stops working, the ICS
provider remains standards-based and independent.

Provider URLs are HTTPS-only, bounded after encoding and generated from the same
snapshot as ICS. External links open in a new tab with `noopener noreferrer` and
no referrer. Provider links never include categories, tags, author data,
unrendered post content, internal recurrence definitions or editor metadata.
Before URL encoding, multi-line description values use a visible ` - ` separator
and multi-line venue/address values use `, `. This preserves field boundaries
after WordPress escapes a rendered `href`; local ICS retains semantic escaped
newlines instead.

## 7. Shared presentation and editor controls

The default component contains one direct `Download calendar file` action. With
two or more providers it can render as either:

- an accessible native `details`/`summary` dropdown; or
- a semantic list of separate action links.

One-provider output remains a direct action in either configured layout. No
JavaScript is required for discovery, keyboard use or download. The default
summary label is `Add to calendar`; authors may replace it with short sanitized
plain text.

Every host exposes the same bounded content settings:

- current context or explicit public one-off event where the host supports event
  selection;
- ICS, Google and Outlook provider toggles;
- dropdown or separate-buttons layout;
- optional short summary label.

Every host styles the same component-scoped semantic classes and custom
properties for action background/text/border, radius, spacing, menu surface and
focus. Gutenberg and Divi accept strict colors and bounded numeric values;
Elementor maps native controls within its widget wrapper. Shortcodes remain theme
inheriting and accept no arbitrary CSS.

## 8. Accessibility, privacy and copy

- Provider names are visible text; icons may only be decorative.
- The summary exposes its expanded state through native semantics.
- Links have complete accessible names and visible focus.
- Touch targets reflow without horizontal overflow at 320 CSS pixels and 200%
  zoom.
- The action never relies on color alone and respects reduced motion.
- Google and Outlook labels clearly name the external service before activation.
- Public documentation states that imported snapshots do not receive later site
  changes and that external providers receive the prefilled event values only
  after a visitor chooses their link.

## 9. Required test matrix

Pure unit coverage freezes:

- one-off and exact-occurrence identity stability;
- timed/all-day, same-day/multi-day, DST, IANA and fixed-offset conversion;
- inclusive-to-exclusive all-day end handling;
- scheduled/postponed mapping and cancelled suppression;
- escaping, CRLF, UTF-8-safe 75-octet folding and injection attempts;
- bounded provider URLs and zero-duration behaviour;
- renderer normalization and no-output states.

WordPress integration coverage freezes:

- public one-off and exact-occurrence downloads;
- draft/private/password/cancelled/dirty/stale/corrupt 404 behaviour;
- GET/HEAD/unsupported method headers and bodies;
- no fallback from invalid occurrence to series;
- current versus explicit event resolution;
- native fallback opt-in and builder-owned suppression;
- shortcode, block, Elementor and Divi parity;
- uninstall cleanup for the new setting only.

Browser and manual interoperability coverage includes:

- keyboard, focus, narrow reflow, no-JavaScript and multiple components;
- dynamic Elementor and Divi editor previews without persistent test data;
- Apple Calendar/macOS or iOS import, Google prefill and Outlook web prefill;
- exact occurrence title/date/location overrides;
- a visible snapshot/no-synchronization explanation in public documentation.

## 10. Explicit non-goals

Version 0.7.0 does not add whole-series export, RRULE generation, subscriptions,
webcal feeds, import, attendee invitations, organizer email, reminders, alarms,
calendar-provider authentication, remote API calls, stored calendar choices,
visitor tracking or automatic updates to an imported event.
