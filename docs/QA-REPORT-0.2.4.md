# QA report — MiMe Simple Events and Calendar 0.2.4

**Date:** 2026-07-28

**Candidate:** MiMe Simple Events and Calendar 0.2.4

**Purpose:** Theme-shell compatibility correction and release qualification

## Result

Release candidate 0.2.4 corrects the missing header and footer observed on the
Taranartos event archive and individual event pages. The defect affected hybrid
classic themes such as Hello Elementor: WordPress exposes block-template support
when a classic theme contains `theme.json`, even though that theme still owns its
site shell through PHP and Elementor locations.

The plugin now registers and selects its full-page block templates only for a
true full block theme. Classic and hybrid classic themes use the PHP fallback,
which calls the active theme's `get_header()` and `get_footer()` paths. Explicit
PHP theme overrides win before block discovery, while full block themes retain
plugin fallbacks, Site Editor customizations and theme block-template overrides.

All local source, package, compatibility and browser gates pass. The site owner
subsequently installed the candidate on Taranartos and confirmed that the live
event pages inherit the intended site shell. The official WordPress Plugin Check
GitHub job remains the final external gate for the release commit because it
runs only after the reviewed changes are pushed.

## Gap audit

The template architecture, core decision path, theme override hierarchy and
visitor tests were reviewed together. Three gaps were found and closed:

1. A classic theme with `theme.json` could be mistaken for a full block theme,
   causing the plugin template to reference header and footer template parts the
   theme did not provide.
2. A readable PHP override supplied by a theme or child theme could still be
   passed through later block-template discovery instead of winning immediately.
3. Existing WordPress smoke checks asserted event content but did not assert the
   complete page shell, so an event could pass while its site header and footer
   were absent.

No second production template-selection path, custom taxonomy template, REST
route or builder-specific full-page replacement was found that could bypass the
corrected decision. Taxonomy archives remain owned by the active WordPress theme.
Elementor Theme Builder content remains delegated through its existing public
location API inside the preserved theme shell.

## Security and privacy review

- The patch adds no endpoint, request parameter, state-changing action, database
  query, option, metadata field, cookie, remote request or production dependency.
- The only new browser action is development-only test-theme activation. It is
  restricted to an allowlisted fixture slug, uses WordPress' administrator page
  and follows the nonce-protected activation URL generated by WordPress.
- Runtime template inputs remain fixed internal filenames and slugs. No request
  value reaches `locate_template()` or `locate_block_template()`.
- Event publication, password protection, bounded public queries, REST
  permissions, escaping, structured data and uninstall behaviour are unchanged
  and were re-exercised by the packaged smoke journey.
- Test themes and internal QA files are excluded from the production archive.
- No privacy contract changes are required.

## Senior developer review

- `wp_is_block_theme()` expresses the actual architectural boundary and is
  available throughout the supported WordPress range.
- Dynamic native render blocks remain registered for every theme because full
  block templates and explicit block content depend on them; only full-page
  template definitions are conditional.
- The PHP override is returned before checking the bundled fallback, preserving
  child-theme ownership and avoiding accidental replacement.
- Full block-template discovery now receives WordPress hierarchy filenames with
  `.php`, allowing core to normalize and resolve the corresponding HTML template
  slugs correctly.
- The implementation is small, has no migration or stored-data impact and is
  backward compatible with the public `wpse_` hooks and identifiers.

## Senior QA review
